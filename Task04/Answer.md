# Task 4

Vehicle has private final regNo, getRegNo(), abstract ratePerHour(), calculateFee(long), calculateFee(LocalDateTime,LocalDateTime), equals(), hashCode() and toString(). TwoWheeler and Car specialize rates; ElectricCar implements chargingFee(). Slot has final floor, number and charging, plus mutable private vehicle; it exposes isFree(), isSuitable(), validated occupy() and release(). ParkingTicket has final id, vehicle, slot, entry, role and pass with getters. ParkingFacility owns Slot[][], ParkingTicket[], PricingRule and collection; enter()/exit() enforce transactions. Pass checks coverage; PricingRule calculates parking fees. MonthlyPass owns registration and YearMonth.

ParkingTicket(Vehicle, Slot, LocalDateTime) chains with this(v,s,entry,"VISITOR",Pass.none()) to the full parameterized constructor. The short constructor supplies defaults without repeating validation. this.vehicle = v distinguishes the current object's field from an argument. Slot and Vehicle constructors reject invalid values so a usable object cannot be created with missing identity or an invalid position.

Java supplies a default no-argument constructor only when no constructor is declared. These domain classes deliberately have no no-argument constructors: an unidentified vehicle or positionless ticket would be invalid. A teaching-only default-plus-setters approach would temporarily violate those invariants. Constructor overloading provides alternative valid creation paths, not permission to skip required information. A duplicate ticket is a view/copy of the same issued ticket ID; a public copy constructor issuing a new ID would misleadingly represent a second admission. Therefore no copy constructor is provided. An immutable ticket reference may be reprinted without mutating admission state.

Conceptually local reference variables and call frames are on the thread stack and instances/arrays are on the heap; the JVM may optimize placement through escape analysis. A reference is not the object. Two references can refer to one Vehicle, as the ticket and occupied slot do; clearing only one reference does not free it.

Alternative: ParkingTicket t = new ParkingTicket(); t.setVehicle(v); t.setSlot(s); t.setEntry(in) requires a final validate step and exposes partial state unless setters are restricted behind a builder. A static factory ParkingTicket.issue(v,s,in) can call the validated constructor and give creation a descriptive name. Factories can cache or return subtypes, but ticket issue must always create a new identity. All three approaches create n fixed-size tickets in O(n) time and O(n) retained space, with O(1) per object. Setters add a constant number of calls/checks; a validating factory adds one delegating call, not a different Big-O. Registration length and UUID/string storage are bounded in this analysis.

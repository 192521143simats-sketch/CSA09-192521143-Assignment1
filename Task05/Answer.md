# Task 5

ParkingTicket has a static AtomicLong NEXT shared by every ticket and every facility in the JVM. static final RUN is initialized once to a UUID and acts as a run namespace. id combines RUN with NEXT.incrementAndGet(). A per-ticket counter starting at zero would repeat values. issuedCount() is static because it describes the class-wide sequence, not one admission. Static initialization expressions suffice; a static block would be appropriate for multi-step constant/configuration setup but is unnecessary here. Occupancy and collection belong to each facility; making them static would mix north and south gate totals. occupancy() counts active entries rather than maintaining an error-prone second mutable counter.

enter() returns a ParkingTicket reference. Passing Vehicle or ParkingTicket passes a copy of the reference value: Java is always pass-by-value. Mutating the referenced mutable object can be visible to the caller, but assigning a parameter to null cannot clear the caller's variable. Tickets and registrations are immutable; the facility owns the array of active references.

After successful exit, active[i] is cleared and the slot releases its Vehicle. The ticket becomes eligible for garbage collection only when no live caller, history list or other reachable reference retains it. In Task05 the local reference is explicitly cleared after exit. Eligibility does not guarantee immediate collection, and System.gc() would only request it. Vehicle collection likewise depends on every remaining reference. No finalizer is used.

Alternative: a counter field per ParkingFacility uses O(k) counter storage for k facilities, rather than O(1) for the shared static counter, independent of n tickets. Local numbers 1,2,... overlap between north and south. IDs such as NORTH-1 and SOUTH-1 with a persistent unique facility prefix solve this if each facility persists its next number. A central durable sequence solves global numbering across processes. Each ticket still stores one bounded ID, O(n) total, under either approach. The implemented UUID namespace makes restart collisions extremely unlikely but is not a durable database uniqueness constraint. The shared AtomicLong makes increment atomic; it does not make the whole facility thread-safe. Allocation, exit and count operations are O(N) in the array implementation; number generation is O(1).

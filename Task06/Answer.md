# Task 6

Vehicle is the abstract superclass. TwoWheeler and Car extend Vehicle, forming hierarchical inheritance. ElectricCar extends Car, forming the multilevel path Vehicle -> Car -> ElectricCar. Java gives each class one direct superclass. Vehicle supplies registration, identity and fee overloads; TwoWheeler adds Rs 10/hour; Car adds Rs 30/hour; ElectricCar inherits the car rate and adds charging through Chargeable. The private registration field is initialized by Vehicle and accessed through getRegNo(), never directly by a subclass.

Each child constructor calls super(regNo). Constructor execution for new ElectricCar("TN01E1") runs Object, Vehicle, Car, ElectricCar in that order; argument evaluation occurs before the called constructor body. Task06's separate TraceVehicle/TraceCar/TraceElectricCar classes print 1 Vehicle constructor, 2 Car constructor, 3 ElectricCar constructor without inserting debugging output into the shared domain classes. super.method() can deliberately invoke the parent implementation when a subclass augments it; protected methods are available to subclasses but the registration remains private. Using a super field access would still require that field to be accessible, so exposing regNo merely to demonstrate it is inappropriate.

Users are represented by a validated role and a composed Pass instead of a Student/Staff/Visitor inheritance hierarchy. A user can change entitlement without changing class, and no other distinct user behaviour is needed.

Alternative: Vehicle has-a VehicleType(registration-independent name, hourlyRate). Example: Vehicle v = new Vehicle(reg, new VehicleType("CAR",30)); fee = ceilHours(minutes) * v.type.rate. Adding a simple new rate can then be a configuration entry without a new subclass. A subclass hierarchy adds a type class and factory registration; composition adds a policy/configuration object and factory registration. Both charge in O(1) for fixed rules; the inheritance vehicle stores O(1) state and dispatch metadata, while composition adds O(1) reference per vehicle plus O(k) shared type objects. A fresh type object per vehicle uses O(n) type objects, which can be avoided by sharing immutable types. Inheritance clearly demonstrates is-a relationships for this assignment; pricing composition is retained for changes that do not fit the type hierarchy.

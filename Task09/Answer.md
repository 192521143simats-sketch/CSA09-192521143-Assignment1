# Task 9

Vehicle is abstract because there is no meaningful generic vehicle rate. Its constructor centralizes registration validation and its private field centralizes identity. ratePerHour() is abstract; concrete subclasses must supply it. Fee rounding, equality and registration access are reusable concrete methods. An abstract base may hold state and constructors while preventing direct instantiation.

Chargeable is an interface because charging is an optional capability, not the parent of every vehicle. ElectricCar can extend Car and implement Chargeable simultaneously. A class may implement further interfaces, such as an auditable or payable capability, without another superclass. These extra interfaces are illustrative and are not added as unused domain classes. Parking payment is a PricingRule/Pass decision; a Payable user interface is unnecessary when the operation already belongs to the facility.

Chargeable.chargingDescription() is a default method providing shared descriptive behaviour. Chargeable.validateUnits() is a static helper called using the interface name and rejects negative energy. Static interface methods are not inherited as instance methods. Pass.none() supplies a no-entitlement object rather than nullable checks. PricingRule is another interface; StandardPricing supplies the original fee policy. Interfaces specify a contract; instances supply behaviour.

Alternative: interface Vehicle could declare getRegNo(), ratePerHour() and a default calculateFee(). Each concrete implementation would then have to store and validate registration and implement equality/hashCode itself, or delegate those duties to another shared class. Interfaces have no per-instance fields or constructors and cannot enforce constructor-time state validation. If Chargeable became an abstract class holding charging state, ElectricCar could extend Chargeable or Car but not both, because Java forbids multiple class inheritance. Composition/delegation could recover both behaviours, adding an object/reference and plumbing. Default interface dispatch and abstract-class dispatch are both normally O(1) per call with respect to type count. Both can keep O(1) state per vehicle; using an extra delegate adds O(1) per-object space and possibly a shared O(k) policy pool. There is no universal exact byte comparison without inspecting the JVM object layout.
